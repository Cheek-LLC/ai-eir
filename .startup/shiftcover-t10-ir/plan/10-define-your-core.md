# Step 10: Define Your Core

## Candidate advantages considered
1. Maria's domain expertise and existing network of Directors of Operations in the QSR
   multi-unit space (right-to-win, but licensable/hireable — a competitor could hire an ops
   veteran too).
2. The SMS-first, qualification-tagged broadcast mechanic itself (currently just a product
   decision, not a technical moat — any competitor could build the same SMS flow).
3. A cross-location backup-worker data asset that improves with scale: as more locations and
   more franchise groups in a metro join, the pool of "who reliably accepts and shows up" for a
   given qualification/location combination becomes a genuinely better-informed match over time —
   this is the only candidate that plausibly gets *stronger* as the network grows.

## The Core
**A cross-location, qualification-matched backup-labor pool and acceptance-reliability dataset
that improves specifically for a given metro as more locations and franchise groups in that metro
join the platform.**
- **Unique:** Not unique on day one (the SMS mechanic itself is copyable in weeks by a
  well-resourced competitor) — but the *data* about which specific workers reliably accept and
  show up for which qualification/location combinations, accumulated per metro, is not something
  a new entrant can replicate without also accumulating usage in that metro.
- **Important:** Directly drives the core value metric from Step 8 (time-to-cover) — a broadcast
  that reaches workers statistically more likely to accept and show up is faster and more
  reliable than a broadcast that doesn't know that yet.
- **Grows:** Gets stronger per-metro as more locations (even from different franchise groups) join
  the same metro's pool — a genuine, if narrow, network effect. **Honest caveat:** this Core does
  not exist yet at meaningful scale; it is a bet on what accumulates after real usage, not
  something ShiftCover has today.

## Resulting competitive advantages
- Faster average time-to-cover than a competitor with no accumulated reliability data in the same
  metro (once the data exists).
- A reason for a *second* franchise group in the same metro to join (bigger shared pool), which a
  single-group-only competitor tool can't offer.

## Core or just a Moat?
**Currently a moat at best, not yet a Core.** At present, with zero real usage, ShiftCover has no
accumulated reliability data — the "Core" described above is a design bet about what could become
defensible, not something true today. The only real advantage that exists right now is Maria's
network (Candidate 1), which is a moat (a real, useful, but temporary and non-compounding
advantage) — a well-funded competitor with a hired QSR-ops veteran could close that gap. This is
stated plainly rather than dressed up as an already-earned defensibility story.
